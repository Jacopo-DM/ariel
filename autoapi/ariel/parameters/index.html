Measured sizes and masses of the modules, and the hinge’s servo.

servo is the datasheet; servo_settings says how the simulated hinge uses it (voltage, holding stiffness, gearbox inertia).

A hinge: a fork on the parent, a cradle holding the servo on the child.

The servo turns the cradle (and the child module) relative to the fork, about an axis across the hinge. Its cable runs back to the core, so its mass grows with the hinge’s distance from the core.

quantity_of(unit: astropy.units.UnitBase, *, allow_negative: bool = False) → pydantic.PlainValidator¶

Build a validator for a finite, scalar quantity (positive by default).

A plain number is refused, and so is a value without a unit where the field has one: radians count as dimensionless in conversions, but an angle still has to be written with its unit.

Parameters:

  • unit (astropy.units.UnitBase) – The canonical unit; the value is converted to it.

  • allow_negative (bool) – Accept zero and negative values (an angle), not only positive ones.

Returns:

A pydantic validator that returns the value in unit. It also reads text with a unit ("59.5 g"), as environment variables give it.

Return type:

PlainValidator

How the simulated hinge uses its DSS-M15 (goal servo-dynamics).

The datasheet says what the servo can do; these settings choose the supply voltage, how firmly it holds its angle, and the gearbox inertia the datasheet leaves out. The methods derive MuJoCo’s joint and actuator values from both.

Configuration for the model, should be a dictionary conforming to [ConfigDict][pydantic.config.ConfigDict].

damping(servo: DSSM15) → astropy.units.Quantity¶

Return the joint damping that gives the motor’s torque-speed line.

A DC motor’s torque falls in a straight line from the stall torque at rest to zero at the no-load speed; a damping of their ratio gives that line.
