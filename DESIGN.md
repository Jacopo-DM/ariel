## Specs

**gl-autodetect** (approved 2026-10-17 with tasks G1-G4; implemented, see Results). Users: anyone running ARIEL (as a library or from `examples/`) on a machine where the default MuJoCo OpenGL backend is unsuitable: no display, no libEGL, no OSMesa, or a driver that crashes. They run a render or a video example and today get a traceback or a hard crash.

Facts the spec rests on (checked 2026-10-17, mujoco 3.8.0): `MUJOCO_GL` is read when `mujoco` is imported (`mujoco/rendering/classic/gl_context.py`), so it must be set before the first `import mujoco` in the process; it only affects `mujoco.Renderer` (offscreen), not `mujoco.viewer`, which always uses GLFW and needs a display; the only code in `src/` that creates a `Renderer` is `ariel/utils/renderers.py` (3 places), and 7 examples create one directly; `examples/re_book/1_brain_evolution_multithreaded.py` documents a hard crash (access violation in `glfwCreateWindow`) when a Renderer is created in a worker thread, so a failing backend can kill its process and each backend must be probed in its own subprocess. On the development machine all three backends fail at `Renderer` creation (glfw: no display; egl: libEGL missing; osmesa: libOSMesa missing), in 0.2-0.5 s each.

Behaviour:
- A *worker* (`python -m ariel.utils._gl_probe_worker <backend>`, imports only `mujoco`, never `ariel`) sets `MUJOCO_GL`, builds a tiny model, creates a 64x64 `Renderer`, renders 5 frames and prints one JSON line: ok, mean render time in ms, error text.
- A *manager* (`python -m ariel.utils.gl_manager`, also callable as a function) runs one worker subprocess per backend valid for the platform (Linux: glfw, egl, osmesa; macOS, Windows: glfw only), with a timeout (30 s per backend), records a crash (non-zero or negative exit code), a timeout or an error as `ok: false` with the reason, and writes `mujoco_user_config.json` in the current working directory (atomic write, lock file against parallel writers). A rich progress bar shows the probe and says it is a one-off.
- Config content: `version`, `platform`, `python`, `mujoco` version, `backends` (per backend: `ok`, `render_ms` or null, `error` or null), `selected` (the working backend with the lowest `render_ms`, ties glfw, egl, osmesa; null if none), `viewer_available` (true if glfw works, i.e. a display exists).
- `import ariel` reads the file if present and, only if `MUJOCO_GL` is unset and `mujoco` is not yet imported, sets `MUJOCO_GL` to `selected`. It never probes and never raises: a missing, unreadable or corrupt file is a warning (corrupt) or nothing (missing).
- Importing a module that needs OpenGL (today `ariel.utils.renderers`; a public `ariel.utils.gl_backend.ensure_gl_backend()` for user scripts) probes automatically when the file is missing, with the progress bar and a one-off message, then applies the result if `mujoco` is not yet imported (otherwise it says the choice takes effect on the next run). Two processes starting at once probe once (lock).
- The config is also refreshed when the recorded `mujoco` version or platform differs from the running one, and on request: `python -m ariel.utils.gl_manager`.
- An existing `MUJOCO_GL` in the environment always wins and is never overwritten.

Acceptance criteria (each a test):
1. Running the manager in a temporary folder writes a valid file (all keys above, correct types); on a machine where nothing works, `selected` is null and `viewer_available` false, the manager exits 0.
2. A worker that crashes (simulated with a fake backend that aborts) or hangs past the timeout is recorded `ok: false` with a reason, the other backends are still probed, and the manager exits 0.
3. With a config whose `selected` is `osmesa` and `MUJOCO_GL` unset, a fresh `python -c "import ariel, os; print(os.environ.get('MUJOCO_GL'))"` prints `osmesa`; with `MUJOCO_GL=egl` preset it prints `egl`; with `selected: null` it prints `None`; with a corrupt file it prints a warning and does not raise.
4. Importing `ariel.utils.renderers` with no file probes exactly once and creates the file; a second import in the same folder does not start a subprocess.
5. Two processes importing at the same moment produce one file and one probe run.
6. A read-only working directory only warns; ARIEL still imports.
7. `pytest tests/unit` passes with the new tests (no real GL needed: workers are faked), `ruff check`, `ruff format --check` and `mypy` stay at zero, coverage stays at least 54%.
8. `.gitignore` lists `mujoco_user_config.json`; the README has a short note (what the file is, how to regenerate, that `MUJOCO_GL` wins).
Not verified here (needs another machine): a run where at least one backend works, and Windows/macOS.

Non-goals: changing the interactive viewer; switching backend while a process runs; fixing examples that import `mujoco` before `ariel` (they keep the default backend and only get a hint); GPU selection or a real benchmark (one small render per backend is the speed measure); setting `PYOPENGL_PLATFORM` (MuJoCo does it for egl itself); a setting to turn the probe off.

Integration points: `src/ariel/__init__.py` (reads config, already sets global state), new `src/ariel/utils/gl_backend.py` (read/apply/ensure, imports no mujoco), `gl_manager.py`, `_gl_probe_worker.py`; `src/ariel/utils/renderers.py` (calls `ensure_gl_backend()` before `import mujoco`, with an isort split and an E402 note); tests under `tests/unit/test_utils/`; `.gitignore`; README. `rich` is already a dependency, so no new dependency. The import-direction rule holds: `utils` imports nothing from the other packages.

Architecture and alternatives:
- Chosen: subprocess-per-backend probe plus a JSON file in the user's working folder, read at `import ariel`, auto-probe on first import of a GL-needing module.
- Rejected: probing in-process (a glfw crash kills the caller, as the multithreaded example documents); documenting `MUJOCO_GL` only (leaves the crash for every new user); config under `~/.config/ariel/` (user preferred the working folder for library use; cost: a new folder re-probes once); probing on every `import ariel` (seconds of delay in every worker process); two modes `view`/`batch` (the viewer ignores `MUJOCO_GL`, so the second mode would change nothing).
- Consequence of the cwd choice: the file belongs to the machine, not the folder, so each new working folder probes once.

Open ambiguities: (a) the staleness rule above (mujoco version or platform change) does not notice a driver change; the manual command covers that; (b) the 30 s timeout and 5-frame, 64x64 measure are my picks; (c) when `mujoco` is already imported at probe time the choice only applies on the next run.

## Decisions

Stack and architecture as found in the repo. Reasons are not recorded unless stated.

- Python ≥ 3.12 with uv for environments and dependencies (`uv.lock`); setuptools build backend; `nox` for task automation (docs only today). Reason: the README names uv; no other reason recorded.
- Simulation on MuJoCo (`mujoco`, `mujoco-mjx[warp]`, `dm-control`); bodies are built as MuJoCo `MjSpec` objects. Reason not recorded.
- Evolution engine in `ariel.ec`: `EA` with operations over a `Population` of `Individual`s stored with SQLModel/SQLAlchemy (database-backed, with restart from the database and an `Archive`). Reason not recorded.
- Body encodings: RoboGen-lite modular robots (`Core`, `Brick`, `Hinge`) decoded from genotypes (tree, CPPN-NEAT, NDE in PyTorch, vectors). The Lynx arm is a separate body family.
- Controllers are CPG-based (`SimpleCPG`, `NaCPG`), and tasks are free-function fitness functions.
- Optimisation libraries available: DEAP, EvoTorch, Nevergrad, plus an in-repo `RevDE`.
- Dashboards (Plotly/Panel) live on the `feature-dashboard` branch, not on `main`; `main` has no plotting dependencies.
- Typing and docs: strict ruff (`ALL`), strict mypy and pyright, NumPy docstrings, 100% coverage target. Free functions are preferred over classes (`.claude/dev/functional_vs_oo.md`); records are pydantic models, see the global-standard decision below.
- Global state at import: `ariel/__init__.py` sets `DATA`, a seeded `RNG` (seed 42) and rich logging. Reason not recorded.

- Image handling: switch `opencv-python` to `opencv-python-headless` (decided 2026-10-17, for goal test-env-green). Reason: `import cv2` fails with `libGL.so.1` missing on machines without that system library, and nothing in `src/` needs a cv2 window. The one live window, in `examples/a_mujoco/3_cameras_in_simulation.py`, moves to matplotlib. Performance hint: if image or camera display ever feels slow, suspect that matplotlib replaced `cv2.imshow`, which is faster for live frames. Implemented in T3 with the version pinned to 4.11.0.86 (the locked opencv-python version; PyPI's newest is a 5.x major). Related to but separate from goal gl-autodetect: cv2 and MuJoCo use different GL paths, so this switch does not settle which `MUJOCO_GL` backend to use.
- gl-autodetect config (decided 2026-10-17, implemented in G1-G4): `mujoco_user_config.json` lives in the user's working directory, not `~/.config`, because ARIEL is used as a library and already keys its outputs to the working directory (`ariel.DATA = cwd/__data__`). Cost: the probe re-runs per working folder although the result depends on the machine, and the file needs a `.gitignore` note. It is regenerated on first run if missing and on request via the manager script; a missing file must never crash import (falls back to MuJoCo's default). The user chose to probe automatically on the first import of a module that needs OpenGL (`ariel.utils.renderers`), with a rich progress bar and a one-off message, not at every `import ariel`, because probing takes seconds and multiprocessing workers also import `ariel`. A preset `MUJOCO_GL` always wins. Linux is tested; macOS and Windows probe `glfw` only and have not been tried.
- Lint/type policy (goal lint-types-policy, decided 2026-10-17 in the config review; implemented in T7-T18): ruff `fix = false`, `unsafe-fixes = false`, lint `preview` off, format `preview` on, ruff pinned to `0.14.*`. Reason (measured): lint preview adds 187 findings from 25 unstable rules, while turning format preview off would make 56 instead of 47 files fail the format check, because the code is already formatted in preview style. Both mypy and pyright are kept (user's choice; pyright to be added to the dev group). Enforcement: add a CI workflow running tests, ruff and mypy, non-blocking until counts reach zero, and fix pre-commit so its tools install from the venv. Outcome: all three reached zero, so those steps are blocking in `.github/workflows/checks.yml`; pyright is informational (`continue-on-error`). pre-commit uses `pre-commit/pre-commit-hooks` v6.0.0 plus local ruff hooks through `uv run --no-sync`.
- Ruff rule policy (decided 2026-10-17, rule-group walkthrough; implemented in T7-T15; the exceptions that were kept are listed in the T15b row). Keep `select = ["ALL"]` with: line length stays 80 and long lines are fixed by hand (E501 239 + W505 95); missing-docstring rules (D100-D107) required in `src/`, ignored in `tests/`; `ANN` required in `src/`, ignored in `tests/`; ERA001 kept (delete the 54 commented-out blocks, they stay in git history); T201 `print` ignored in `examples/` and kept in `src/` (implemented as per-file ignores for `examples/**`, `src/ariel/body_phenotypes/lynx_mjspec/unified_pipeline/**`, `cppn_neat/tests.py` and `simulation/example_usage.py`, plus `PLR0915` for the generated `john_set.py`); COM812 ignored (conflicts with the formatter; ruff's docs advise this); TRY003 ignored, EM101/EM102 kept; `[lint.pylint] max-args = 8`; every other rule (SIM, SLF001, PLC0415, PT011, ARG, ...) kept and fixed, with no test exemptions. Measured with this draft config on 2026-10-17: 976 findings in `src` + `tests` (803 + 173; was 1330), `examples/` 1274 (not in scope: not checked by any command in CLAUDE.md). mypy: `[mypy-quaternion.*]` switches from `follow_untyped_imports` to `ignore_missing_imports`, which takes mypy from 262 to 236 errors.
- Entry point: no console script; `[project.scripts]` is removed rather than adding `ariel.__main__` (decided 2026-10-17). Reason: the user does not want a CLI. Done in T1.
- Dashboards leave `main` for a `feature-dashboard` branch, to be revisited once the core is fixed (decided 2026-10-17; done in T4, T5). Reason: untested, three near-duplicate versions, about 5.5k lines. The branch was cut at `6ab657f` (Merge T3), so it keeps the dashboard dependencies and none of the later lint and type work.
- Wiki sources for MuJoCo come from the Read the Docs `/stable/` docs (the newest release), not `/latest/` (development branch) and not a pinned `/en/3.8.0/`; decided by the user 2026-10-18. Consequence: the docs describe 3.16.0 while `uv.lock` pins 3.8.0, so a page's default can differ from the installed engine; defaults for ARIEL are read from the installed engine (`mjcf_defaults_3_8_0`) and every MuJoCo wiki page carries a version note. Upgrading MuJoCo to match is a separate, approval-needing dependency change (PLAN.md, Known problems).
- `examples/` and `docs/` are excluded from ruff (`ruff.toml` `exclude`) and mypy (`mypy.ini` `exclude`), so the user's global Python gate covers `src`, `tests` and `setup.py`. Decided by the user 2026-10-18 (this is a deliberate narrowing of the gate's scope, asked for and approved, not a loosened rule). Reason: they are scripts and notebooks with no tests behind them; `mypy .` reported about 500 errors there (missing annotations, untyped `evotorch` and `glfw` imports, an import of the missing module `decoders.score_cube`) and `ruff` about 1,550 findings; fixing them changes nothing the tests can check. They can still be linted by naming the path (`ruff check examples`; ruff checks explicitly named paths unless `--force-exclude` is set).

- Records are pydantic v2 models (global-standard GS6 and GS9, decided 2026-10-18, user chose full models for the tree genome). Base classes `FrozenModel` (frozen, `extra="forbid"`) and `MutableModel` (`extra="forbid"`) live in `ariel.parameters.base_model`. Converted: `TreeGenome`, `TreeNode`, `TreeEdge` (edges keep extra keys, so `extra="allow"`), `GLConfig` and `BackendResult` (the file is read back from disk, possibly written by another version, so unknown keys are ignored), `ArmConfig`, `PolicySpec`, `EvalConfig`, `BetaParams`, and the private candidate and placed-module records of the best-first decoder. Dict forms that cross a boundary (`TreeGenome.from_dict`, `validate_genome_dict`, `Genome.from_dict` of the CPPN) are parsed with `model_validate`. Exceptions, each marked `# ruff: ignore[banned-api]  # reason` on the import: `Controller`, the seven `*World` dataclasses, `PerlinNoise`, `TableWorld` (behaviour first: they build or wrap something after init, the fields are settings). Not converted and not flagged by ruff: plain classes that only hold fields (`Node` and `Connection` in `cppn_neat`); the standard would count them as records, listed in PLAN.md.
- Untyped libraries sit behind typed wrappers or stay untyped at the import: `quaternion` through `ariel.utils.quaternions` (two functions, two `# type: ignore[no-untyped-call]`); `mujoco` stays untyped (`ignore_missing_imports`, `follow_untyped_imports = False`) because its `.typings` stubs do not parse in mypy (syntax error in `_specs.pyi`) and are written for pyright; `torch` and `nevergrad` are followed (`follow_untyped_imports = True`).

- NA-CPG (`simulation/controllers/na_cpg.py`), re-implemented 2026-10-18 from Tong et al., "NA-CPG: A robust and stable rhythm generator for robot motion control", Biomimetic Intelligence and Robotics 2 (2022) 100075, equations 2 to 12, because three diverging files had left the meaning unclear. The old code differed from the paper in four ways that changed the output: the amplitude term was `alpha (1 - r^2)^2` where the paper has `alpha (1 - r^2)`; `r^2` ignored the offset `b` (paper: `x^2 + (y - b)^2`); the state buffer `xy_dot_old` held the previous state, not the previous derivative that `zeta` and the constraint need; the constraint was a fixed clamp of 10. Also missing were the coupling coefficient `h` and the offset in the coupling term. Kept from the old files: the five parameter groups (`phase`, `w`, `amplitudes`, `ha`, `b`), `BetaParams`-sampled initial values (now per instance, seeded, with ranges bounded to physical values), `angle_limits` with `clipping` and `clamping_error` (mean distance to the limits), the setters, `save`/`load`. Dropped: the `normalize` option and `duration` of `na_cpg_norm.py`, which are not in the paper (there "normalized" means the amplitude is fixed to 1 and `theta_i = A_i y_i`), and the class that could not be imported. The update is vectorised over the oscillators (paper section 2.3). Start state: each oscillator on its limit cycle at its own phase, `(cos phi_i, sin phi_i + b_i)`, derivative zero, so coupled oscillators start phase locked; `reset_state()` recomputes it from the current parameters. The constraint function: the paper fits `CF(w)` to the largest second derivative per angular frequency and does not publish the fit, so the default is `CF(w) = CONSTRAINT_MARGIN * w^2 * dt` (the largest change of the derivative per step on the unit circle, margin 3 covers `ha` up to about 0.4); the old research notebook `tests/functional/cpg.ipynb` can still set a cubic through the attribute `coefficients` (highest power first). Defaults follow the paper: `alpha = 30`, `dt = 0.01`, `ha = 0.4` as the asymmetric example. Measured with the tests: amplitude within 2 % of the set value for a single oscillator and a 4-chain (paper: 5.3 %), a share of 0.32 of the period below zero for `ha = 0.4` (theory 0.30).

- `VectorDecoder.vectors_to_graph` (2026-10-18), direct decoding: each vector holds one value in [0, 1] per module except the core (`num_modules - 1`). Module `k` takes its type from `type_vector[k - 1]` (BRICK, HINGE, NONE; NONE is left out), its parent and face from `connection_vector[k - 1]` (one free `(parent, face)` slot of the modules placed before it, so the graph is a tree by construction and there is always a slot: the core has 4 faces and every placed module offers at least as many as it uses), and its rotation from `rotation_vector[k - 1]` among the rotations its type allows (`ALLOWED_ROTATIONS`). Values map through `assign_symbols_from_range`; a slot is chosen by index because that helper treats a list of tuples as per-element symbols. The user asked what the choice changed and did not pick, so this was chosen for them: it matches the unfinished code and needs no invented rule. Deleted with it, as dead and untested through the public entry: `decode_vector_to_graph`, `set_module_types_and_rotations`, `apply_connection_constraints`, `_types_from_vector` of `VectorDecoder` (copies of `HighProbabilityDecoder`'s) and their tests. Reversible through git history.

- mujoco-units seeds (`simulators/mujoco/seeds.py`, MU3, 2026-10-19): `Seeds` is a `FrozenModel`, not a `pydantic_settings.BaseSettings`, because nothing reads seeds from the environment and the global rule shares one base class; each quantity is validated by a `PlainValidator` that needs an astropy `Quantity` of the right dimension, a scalar, positive and finite, and stores it in one canonical unit (m, m/s, rad/s, m/s^2, kg/m^3, Pa s), so later formulas read plain SI numbers; `1/s` counts as `rad/s` (astropy `dimensionless_angles`). `Seeds.replace(**changes)` re-validates (`model_copy(update=...)` does not, see Gotchas). `joint_frequency` default 100 rad/s (about 16 Hz, a stiff hobby servo; judgement, the user asked for the seed on 2026-10-19 without a value; 200 rad/s was tried and made `gamma / omega_max` equal to the advection limit, 2.5 ms, so the binding term flipped on rounding); standard gravity is the plain number 9.80665 because `astropy.constants.g0` and `astropy.units.g0` are invisible to mypy. astropy ships no type hints, so the one call to `Quantity.to` sits in `_to` with a single `# type: ignore[no-untyped-call]`.

- mujoco-units settings (`simulators/mujoco/settings.py`, MU5, 2026-10-19): a setting is a path into `mujoco.MjSpec` (`option.timestep`, `visual.global_.offwidth`, `default.geom.solref`) with a kind (`seed`, `formula`, `fixed`), a reason and a source. Defaults are read from the installed engine by walking the spec objects (`read_object`), not typed in, so an upgrade shows up as a changed default; enums become integers and arrays tuples of floats. Every setting that ARIEL does not override is `fixed` with a per-section reason and source (the XML reference, the wiki page, the installed engine); a reason per attribute would be 157 hand-written sentences with no extra information. Overrides are `option.timestep`, `gravity`, `density`, `viscosity` (seeds and formula), `default.geom.solref` and `friction` (formula and seed), and the four choices ARIEL already made in the old `MujocoConfig` (`integrator` implicitfast, `balanceinertia`, `degree` False, offscreen 960 x 1280). `compiler.eulerseq` (a character vector) and `stat` (compiler output) are left out. `visual.global` is skipped because it is the same object as `visual.global_`.

- mujoco-units MJCF (`simulators/mujoco/mjcf.py`, MU7, 2026-10-19): `build_spec` sets every setting on a fresh `MjSpec` by its path; `generate_xml` is `spec.to_xml()` plus one attribute. Found by testing: `MjSpec.to_xml` writes only values that differ from the engine defaults (so the file is the list of differences, 10 of 156 with the default seeds, and every other value is the installed engine's default) and never writes `compiler.balanceinertia`; `generate_xml` adds `balanceinertia` by string insertion so a reload gives back every setting (a test reads the loaded file with `read_spec` and compares all 156). Consequence for the goal text 'one MJCF that holds all values': the file holds the differences; the full table is printed by `python -m ariel.simulators.mujoco` and, from MU9, written to `docs/source/mujoco_parameters.md`. Writing every default into the XML by hand was rejected: it needs a mapping of 156 spec names to XML names and keywords (`angle`, `cone`, `<flag>`, `<lengthrange>`) with no test that the mapping is right, for a file the engine reads the same either way. `compiler.authored` (a bit mask the XML parser sets) is not a setting and is skipped. The risk of implicit defaults (a future MuJoCo changing one) is covered by the MU9 test, which fails when the regenerated table differs from the document.

- mujoco-units BaseWorld (MU8, 2026-10-19): `BaseWorld._init_spec` calls `build_spec(Seeds())`, an `MjSpec` with every setting set, not `MjSpec.from_string(generate_xml(...))`. Reason: the spec is exact, while the XML text keeps about six significant digits and needs the `balanceinertia` patch; the XML stays the exported, inspectable form (`--out`, MU9 docs) and a test proves the two read back the same 156 settings. The viewer look that `_init_spec` used to set by hand (headlight, rgba, azimuth, elevation, map, scale, shadow size) moved into `settings.CHOICES` as fixed choices with the reason 'what ARIEL already used', so the world code sets no setting itself. `MujocoConfig` stays with `floor_name` only because four worlds read it; it is a candidate to become a class attribute in the physics-bugs goal. Float comparison for 'differs from the engine default' uses a relative 1e-6 because the engine stores some values (the whole `visual` section) as float32.

## Rejected approaches

- Keeping `opencv-python` and documenting `sudo apt install libgl1` only: fixes one machine, leaves CI and new users to hit the same error.

Conclusion: `alpha` 0.05 is adequate (halving h twice moves the path by at most 0.01 m and the peak force by at most 10%); `gamma` was not exercised because the joint limit (5 ms) is not the binding term; `kappa` stays judgement. The spider barely walks (under 0.1 m in 10 s), so the study says little about fast gaits. Script was in the scratchpad, not kept. |

## Gotchas

See "Things that bite" in CLAUDE.md for repo-wide ones. Design-specific ones:

- Band edges need a tolerance. With the default seeds the timestep is advection-limited, so `courant = h * v_max / L` equals `alpha` (0.05) up to rounding (0.05000000000000001), which is the upper edge of its band; `simulators/mujoco/bands.py` compares edges with a relative tolerance of 1e-9. Likewise a default that ties two limits of the timestep flips the binding term on rounding (`joint_frequency` 200 rad/s tied with the advection limit and was changed to 100).

- `HighProbabilityDecoder` and `Blueprint` use attributes they never define; `OlympicArena` cannot be instantiated (abstract `_expand_spec`, a misspelling of `_extend_spec`); `SimpleTiltedWorld` reads `_terrain_color`, which is never set. These are the `# known bug` ignores listed in PLAN.md.
- `mujoco.viewer` (used by about 20 examples) always uses GLFW and ignores `MUJOCO_GL`; only `mujoco.Renderer` honours it. A GLFW `Renderer` created in a worker thread crashes (`examples/re_book/1_brain_evolution_multithreaded.py` documents an access violation in `glfwCreateWindow`), which is why every backend is probed in its own subprocess.
- The 3 `# noqa: E712` comments in `ec/archive.py` and 1 in `ec/ea.py` are needed: SQLAlchemy columns must be compared with `== False`.
- `test_all_heightmap_functions` (`tests/unit/test_simulation/test_environments/test_environments.py`) inspects the namespace of `simulation/environments/heightmap_functions.py`, so that module uses `typing.cast` and must not import `cast` as a name.
- `opencv-python-headless` has no windows: `cv2.imshow` does not work. If camera or image display ever feels slow, suspect that `examples/a_mujoco/3_cameras_in_simulation.py` now uses matplotlib instead of `cv2.imshow` (that example was never run, there is no display on the development machine).
- A one-line docstring that does not fit in 80 columns cannot satisfy both E501 and D200 (`D212` is ignored in `ruff.toml`), so T12 shortened such summaries until they fit on one line.
- `ruff format` also formats the notebooks under `tests/functional/` (cell source only); pre-commit's ruff hooks only look at `src/` and `tests/`, while docs and examples keep about 1,270 findings.
- Importing `ariel.utils.renderers` in a folder without `mujoco_user_config.json` runs a probe of a few seconds and writes the file into that folder; `tests/conftest.py` presets `MUJOCO_GL=glfw` so the test suite never does this in the repository.
- `uv run --no-sync pyright` downloads Node and the pyright npm package into `~/.cache/pyright-python` (229 MB) on its first run.
- The MuJoCo docs at `/stable/` describe 3.16.0 (changelog of 2026-10-14) and this repo has 3.16.0 installed since 2026-10-19 (MU1); the wiki page `mjcf_defaults_3_8_0` is the old measurement and `mjcf_defaults_3_16_0` lists what changed. Read defaults from the installed engine, not from the wiki, and fetch versioned pages (`/en/3.16.0/`) when a value must match.
- A callback `Protocol` with `/` before `*args, **kwargs` accepts only callbacks whose first two parameters are positional-only too (otherwise a caller's `**kwargs` could clash with their names): see `ControlCallback`; the test callbacks and `cppn_decoding` use `/`.
- `np.generic` and bare `np.ndarray` count as explicit `Any` for `disallow_any_explicit`; use a concrete dtype (`NDArray[np.float64]`, `np.void` for quaternion arrays). A PEP 695 `type X = NDArray[...]` alias is flagged where a plain annotation is not.
- The probe worker sets `MUJOCO_GL` in the calling process; a test that runs it must restore the variable (`monkeypatch.setenv`), or a later spawned worker that imports mujoco can hang. `mujoco_worker` also sets `OMP_NUM_THREADS` and friends in the caller.
- ruff `--select X --fix` with `RUF100` in the list removes valid `ruff: ignore` comments for rules that were not selected; this cost a revert in GS5. Check with the full rule set.
- Pydantic copies the dicts and lists it validates, so a model built from your own list no longer shares it. `TreeGenome.to_dict()` returns copies, not the live edge list.
- `BaseModel.model_copy(update=...)` does not validate the update, so a frozen settings model copied that way skips its validators and warnings. Re-validate with `Model.model_validate(model.model_dump() | {...})`. Computed fields still recompute on a copy.
- The global command guard (`~/.claude/hooks/python-guard.sh`) refuses a Bash command that contains the text of a pip install even inside a heredoc of page content; reword the text or write the file with the Write tool.
- mypy 1.18.2 stops with `INTERNAL ERROR` (AssertionError in `expand_type`/`visit_param_spec`) on an attribute access through a `ParamSpec`-generic class (`EAOperation[**P]`, `bound.kwargs` in `tests/unit/test_ec/test_ea.py`). After a crash mypy reports only the errors found before it, so the count looks small and grows when the crash is avoided: check that a `mypy .` run ends with `Found N errors` or `Success`, not `INTERNAL ERROR`.
- Coverage can depend on randomness (2026-10-19): `decoders/hi_prob_decoding.py` lines 191-192 (a module whose best type is NONE) were reached only when a test with random probability spaces happened to pick NONE, so 2 of 12 parallel runs fell to 99% and the user's Stop gate reported `pytest` as failed (exit 3). `pytest-cov` then writes its "Coverage failure" message through `terminalreporter.write`, which `pytest-modern`'s `ModernTerminalReporter` lacks, so the run ends in an `INTERNALERROR` that hides the cause. Found by running the suite 12 times in parallel with `COVERAGE_FILE` set per run and reading each with `coverage report --data-file=... --show-missing`. Fixed with a deterministic test (`test_hi_prob_none_module_loses_all_its_connections`). If the gate fails on pytest again, do the same.
